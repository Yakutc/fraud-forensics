
Обнаружение мошеннических транзакций
Колонки с ответом в данных нет, обучать модель не на чем. Восстановлен скрипт, которым генерировались мошеннические строки, и поиск ведется по его следам. Метрика AUC, ей важен только порядок, поэтому вместо вероятностей можно отдавать любые монотонные числа.

Найденные закономерности:
Первая группа: сумма как доля баланса.

amount = balance * random.uniform(0.80, 0.95)

В полосе [0.80, 0.95] находится 462 строки, в соседних полосах той же ширины в среднем 2.5. Разница слишком большая, чтобы быть случайной. Все 52 строки с отрицательной суммой тоже здесь, и у всех отрицательный баланс, то есть знак генератор сохранял

Вторая группа: круглые копейки.

amount = randint(500, 5000) + choice([0, 0.5, 0.99])

В окне [500, 5000) 176 строк с копейками 0, 50 или 99, хотя при обычной доле 3% их должно быть около 47. Дробные части у них бывают только 0, 0.5 и 0.99.

Третья группа: тот же генератор достает и ниже 500. Там 1179 строк с такими копейками, и по флагам видно примерно 15 лишних мошенничеств. Они почти без признаков, поэтому обычный скор их топит. Под них сделана отдельная полоса

расчет:
Для каждой строки считается логарифм отношения правдоподобий: насколько вероятнее увидеть такую сумму и такие флаги у мошенника, чем у нормального. Нормальные суммы описаны логнормальным распределением (shape 1.495, scale 32.955), мошеннические равномерными законами выше. Флаги: иностранная операция, ночь, рискованный MCC, тип устройства. Частоты флагов у мошенников считаются с вычетом фона, который случайно попал в выборку.

Далее три полосы: кандидаты сверху, мелкие круглые копейки посередине, остальные снизу. Внутри полосы сортировка по скору. Для AUC этого достаточно: пары «нормальный-нормальный» все равно не считаются

Запуск:
python solution.py --input transactions.csv --output submission.csv

Оба аргумента необязательные, по умолчанию берутся transactions.csv и submission.csv. На выходе две колонки: transaction_id, prediction.
